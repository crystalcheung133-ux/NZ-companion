# Travel Engine — NZ Companion RC24.7 Implementation Report

## Audited architecture

- `data.js` is the canonical static source for Guide places/categories/order, booking records, timeline days, daily driving routes, and export itinerary data.
- `booking-authority.js` applies Studio Mode booking overrides without changing the data architecture.
- `itinerary-authority.js` owns timeline override resolution.
- `trip-runtime.js` renders Trip Booking lists/details; `guide-runtime.js` renders Guide cards and actions.
- `navigation.js` and `navigation-config.js` own page/query construction. Place URLs use canonical `id`; RC24.7 booking links use `bookingId`.
- `export-runtime.js` reads the same resolved itinerary view, so route/timeline corrections flow into share and printable exports.
- `sw.js` owns versioned offline caching; `pwa.js` retains the existing update lifecycle.
- Existing CI covers syntax, release hashes/manifest, HTML structure, entity linkage, addresses, timeline order, and UX contracts.

## Deep-link design

Guide Booking links are normal internal links built through `NAVIGATION.build('trip',{query:{bookingId}})`. On `trip.html`, `trip-runtime.js` resolves the stable booking ID through `BOOKING_AUTHORITY` and opens the correct accommodation/activity detail after DOM readiness. The query remains in the URL, so refresh/direct navigation restores the target. Normal link navigation preserves browser Back behaviour.
