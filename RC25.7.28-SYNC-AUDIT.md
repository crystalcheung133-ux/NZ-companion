# RC25.7.28 Cross-Device Sync Audit

## Verdict
PASS WITH OBSERVATIONS.

The portable NZ CI passes. Booking, Documents, Expenses and Moments now share a predictable startup/foreground/online/30-second visible refresh contract. Timeline publication is manual. A real two-device browser test remains pending until this candidate is deployed. The bundled `engine-ci/run-all.sh` is not portable as shipped because it points to `ci-tests/...` for files that are actually under `engine-ci/...` and also expects a missing `starter/` fixture tree; this is an Engine CI packaging issue, not a runtime sync failure.

## Implemented contract
- Booking: Studio-only edits remain in `BOOKING_AUTHORITY`; local save pushes directly to Supabase `trip_bookings`; readers pull on startup, foreground, online, and every 30 seconds while visible. Booking save does not publish the whole trip.
- Timeline: Studio draft/save no longer auto-publishes. `Publish Latest Trip` is the deliberate release boundary for timeline/routing/derived itinerary changes.
- Documents: everyone can upload; uploader identity (`ownerKey`) can edit/delete own uploads; Studio can edit/delete all; only Studio can change Booking/Timeline links. Sync runs on startup, foreground, online, and every 30 seconds while visible.
- Expenses: existing multi-writer record-level merge, tombstones, startup/foreground/online + 30-second visible polling retained.
- Moments: existing multi-writer record-level sync, startup/foreground/online + 30-second visible polling retained.

## Important Documents fix
The prior Documents implementation could lose an offline delete retry because `sync()` started from `read()`, which filters tombstones. RC25.7.28 merges from `readRaw()` and retries tombstones and pending metadata before pulling remote rows. This prevents a deleted document from being resurrected merely because the delete happened offline.

## Expected cross-device timing
- Same visible page/device: local UI updates immediately after local save.
- Other device already open and visible: next poll, worst case about 30 seconds plus request time.
- Other device returns from background: foreground sync queued after about 100 ms.
- Device reconnects: sync queued after about 50 ms.
- Fresh page load: sync queued immediately after DOM ready.

## Supabase verification
`trip_bookings` was created in the connected project with RLS enabled and authenticated SELECT/INSERT/UPDATE policies. Existing `trip_documents`, `trip_expenses`, and `trip_moments` also have RLS enabled.

The project's anonymous-sign-in architecture means an anonymous browser session receives the Postgres `authenticated` role. Supabase's security advisor therefore flags broad authenticated policies, including existing Expenses/Moments/Documents policies and the new Booking table. This matches the current private-trip architecture but is not strong per-person server-side authorization.

## CI
`sh ci-tests/run-all.sh`: PASS, including the new RC25.7.28 cross-device sync contract.

`sh engine-ci/run-all.sh`: FAILS before meaningful execution because the runner references missing paths/fixtures in this portable ZIP (`ci-tests/test-syntax.js`, etc., while those files are under `engine-ci/`, plus missing `starter/`). This pre-existing packaging defect should be repaired separately if canonical Engine CI is intended to run from the NZ artifact.
